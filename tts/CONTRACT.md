# Local TTS sidecar contract

Every local TTS container (`tts/<name>/`) runs one HTTP server on port **9000** inside the compose
network (not published). The bot (`bot/services/gpu.py`, `bot/services/local_tts.py`) relies only on this.

## Control (VRAM)

The RTX 3060 has 12 GB, so only one heavy model may be resident. The bot decides what is loaded.

| Request | Behaviour |
|---|---|
| `POST /load` | Load the model onto the GPU; respond `200` only when synthesis is ready. Idempotent. On failure `500` with a short text reason. |
| `POST /unload` | Free **all** VRAM held by the model (process exit or real release); respond `200` when done. Idempotent. |
| `GET /status` | `200 {"loaded": bool}` |

The container starts with nothing loaded.

## Synthesis

`POST /v1/audio/speech`, JSON:

```json
{"input": "[irritated] Так, подождите. Кто вы такой?", "voice": "granny"}
```

- Response: `200`, `Content-Type: audio/pcm`, body = **raw PCM16 little-endian, mono, 24000 Hz**, streamed
  (chunked) as soon as audio is available. No WAV header.
- `409` if not loaded, `400` on bad input, `500` on synthesis error (short text body).
- `voice` selects the reference set `/voices/<voice>/` (mounted from `${MODELS_HOST_DIR}/voices`); unknown
  voice falls back to `/voices/default/` or the model's built-in voice.
- `input` is Russian text that may contain canonical emotion tags in square brackets, anywhere before a
  phrase. The sidecar maps them to its own mechanism and never speaks them:
  `[calm] [warm] [irritated] [angry] [laughs] [sighs] [confused] [sad] [surprised]`.
  Unknown `[...]` tags are stripped.

## Reference voices

`/voices/<voice>/<emotion>.wav` (mono, ≤ 12 s) + `/voices/<voice>/<emotion>.txt` (exact transcript),
emotion ∈ the tag set above plus `neutral`. Generated by `scripts/make_voice_refs.py` (synthetic voices,
no real people).
